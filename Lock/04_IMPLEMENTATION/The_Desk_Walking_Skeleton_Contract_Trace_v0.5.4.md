# The Desk - Walking-Skeleton Contract Trace v0.5.4

**Status:** LOCKED FOR BUILD 1-2
**Date:** October 1, 2026
**Purpose:** Prove that the active specs define one coherent artifact path from frozen evidence through launch-format craft critique, audited writing, rendering, and validated clean master before automation broadens.
**Supersedes:** v0.5.3 (retained as history; its hashes are predecessor constants and are not current)

## 1. Fixture scope

Use one synthetic or rights-safe football post-match fixture. It should be deliberately small but exercise the active contracts, including:

- one verified result/stat fact;
- one attributed reporting claim;
- one `hedged_only` claim;
- one supporter-mood claim with a bounded observation set;
- one lore/context claim;
- one `desk_derived` claim with reconstructable derivation;
- one silent market/calibration input structurally withheld from the writer;
- one continuity item or eligible prior prediction;
- one sensitivity constraint or explicit `none` state;
- one canonical pronunciation plus one current provider/voice rendering and one stale rendering;
- all nine required `post-event-launch-v2` slots represented as brief-owned program blocks;
- one claim-backed launch `comprehension_target` with no repetition count;
- one independent Craft Critic result and at most one substantive craft revision inside `SCRIPTED`;
- one Tully closing-synthesis block/job;
- Simon behaving as an emotionally present supporter avatar without collective-membership language;
- Gaz behaving as a listening/processing thinker with dry humor rather than a serial stat dispenser;
- at least one two-speaker render block;
- one named mechanical-failure TTS reroll plus an append-only trigger/selection record;
- one external-content prompt-injection string stored as inert evidence data;
- one adapter-level literal provider-syntax escaping vector;
- the launch pre-publish-review and Operator Repair sockets from ADR-003.

No live ingest, live web search, publication, large Craft Library retrieval system, or audience-metric optimization is required in the walking skeleton.

### 1.1 Corrective fixture topology

Fixture v0.4.5 has two program paths (two fresh root runs and two fresh attempts bound to show-configuration version 2) over the same controlled content:

- `purpose=evaluation`: proves the content/artifact pipeline through `VALIDATED` and is barred from READY;
- `purpose=production`, `publication_enabled=false`: reuses exact immutable artifacts where valid, materializes a deterministic fixture master, enters READY, mints the internal fixture Episode/GUID, and proves review/repair semantics without publication.

A deterministic `fixture_tts` adapter is legal for this proof. The fixture revalidation record proves interface/binding/expiry behavior only; it is not the later full live revalidation system.

Confirmed READY repair creates a child attempt. The parent READY attempt never moves backward. Every repaired READY candidate gets a fresh wait.

The one automatic reroll is caused by a named mechanical validation failure, not subjective dissatisfaction.

### 1.1 Fixture conformance gate

Before implementation hashes or persists the fixture, validate each artifact against the field ownership and closed enums in its active owning spec.

The fixture must fail fast if:

- an enum value is outside the owning registry;
- a required field is missing;
- a lower-layer artifact duplicates a higher-layer source of truth;
- an artifact carries a field whose shape conflicts with the active spec;
- a fixture mutation cannot fail for the named reason;
- a comprehension target contains a repetition quota such as `repeat_count` or `desired_reinforcement`;
- the Craft Critic invents a sports fact, claim, or rewrite rather than returning diagnosis;
- a craft revision expands the frozen factual universe;
- character behavior contradicts the no-counterfeit-membership boundary.

The fixture is an executable contract, not a convenient example. If fixture bytes and an active spec disagree, the active spec wins and the fixture must be rebuilt.

### B. Showrunner Brief v0.1.3

**Consumes:** planner view of the frozen package only.

**Creates:** selected episode mode/template; central question/editorial spine; selected/omitted beats; context selections; participant leads/evidence assignments; ordered program blocks; runtime budgets; feature decision; prediction tasks if configured; sensitivity constraints; structured exclusions; and, for the launch format, a small optional set of claim-backed `comprehension_targets`.

A comprehension target identifies an editorial question/idea worth enough runway to survive imperfect attention. It may reference supporting claims, related beats, forward horizon, useful treatment lenses, and whether it is a closing-synthesis candidate. It does **not** contain an invented answer or any numeric repetition target.

Program blocks are owned here. The launch `wrap` slot is internally treated as a **closing synthesis** job. The planner supplies the job and permitted claims, not the final wording or a fixed recap checklist.

**Cannot create:** new facts, new evidence, new analytical assertions outside packaged claims, stronger usage permissions, spoken wording, performance direction.

**Invariant test:** every factual premise and every asserted insight/implication available to downstream writing resolves to permitted frozen claims.

**Canonical brief hash:** `36fb22d03300206d3181959a100f2911c2b27d9ff72379f21831d32a4bd5c475`

## 3. Required failure drills

The prior drills remain required, including package idempotency, Pass-2 diff-lock failure, provider-syntax escaping, prompt-injection inertness, stale-pronunciation blocking, retry/reroll distinction, selection persistence, program-block boundary enforcement, paid-call concurrency, purge tombstones, and a **fixture/stub revalidation contract drill**. Full live revalidation remains deferred to its later build.

Base-request conformance has two explicit vector sets: `render_request_projections.json` contains nine real block baselines, while `base_request_hash_conformance.json` contains the nine P&R §24 sensitivity/stability tests and row-level inputs needed to verify the projection function itself.

Add the following v0.5 writing-craft drills:

1. **Critic fact invention:** a Craft Critic finding that adds a new sports proposition fails the critic contract.
2. **Critic rewrite:** a Craft Critic payload that supplies replacement dialogue rather than diagnosis fails the critic contract.
3. **Good Thing x50:** a candidate that repeatedly performs the same successful character/joke/disagreement mechanism is diagnosable as device saturation even when wording varies.
4. **Visible learning language:** routine phrases such as "the key takeaway" or explicit mention-count choreography fail the launch craft profile when not editorially justified.
5. **Detached Simon:** converting Simon into a pollster who merely reports that supporters are concerned is a craft failure where the supporter evidence supports a direct emotional stance.
6. **Counterfeit Simon:** collective supporter-membership language remains disallowed even when stronger emotional presence is requested.
7. **Argumentative-by-default Simon:** repeated conflict inserted without evidence/position tension is a craft failure; warmth with Gaz is the baseline.
8. **Stat-vending Gaz:** serial stat drops without listening, delayed processing, qualification, or conversational consequence are diagnosable as character flattening.
9. **Compulsory Gaz punchline:** adding a dry joke to every Gaz turn is device saturation, not character fidelity.
10. **Reinforcement quota:** any `repeat_count`, `desired_mentions`, or numeric reinforcement requirement in the launch comprehension metadata fails conformance.
11. **Brittle comprehension:** a primary claim-backed target that is expressed once in a fragile sentence and never meaningfully re-entered may be flagged for craft revision.
12. **Redundant reinforcement:** merely paraphrasing the same point without a new conversational job is not accepted as semantic reinforcement.
13. **Unsupported implication:** a forward-looking factual/analytical implication not supported by packaged claims fails the normal claims/audit path; craft value cannot rescue it.
14. **Flat closing summary:** a generic recap that merely lists prior points is diagnosable as a weak closing synthesis.
15. **Closing formula:** forcing every Tully close into a fixed point-count/joke/next-match template is device saturation.
16. **Launch-scope leakage:** a future format does not inherit the launch information/comprehension-density strategy merely because Writing Craft v0.1 exists.
17. **Craft-review persistence:** the critique and any child revision remain immutable/inspectable; no in-place rewrite of Pass 1.
18. **Craft revision budget:** a second substantive craft revision in Build 2 fails the configured budget and routes to typed halt/operator handling rather than silently looping.

## 4. ADR-003 / Operator Repair closure drills

The v0.3 operating-model drills remain required:

1. normal render blocks never enter per-block human approval;
2. subjective acoustic dissatisfaction does not auto-reroll;
3. required READY review cannot bypass into REVALIDATED without external resolution;
4. review timeout halts rather than publishes;
5. performance-only repair forks a child attempt, reuses exact script identity, and invalidates/rebuilds only the correct downstream artifacts;
6. programming repair invalidates Brief and all downstream artifacts;
7. factual-correction feedback routes to evidence/claims rather than direct spoken-text editing;
8. repair cannot override silent/rights/sombre/implied-access gates;
9. the original READY candidate and superseded artifacts remain immutable and inspectable;
10. the performance-repair and programming-repair fixture examples run as **mutually exclusive reset scenarios** from the same READY seed, each with its own confirmed repair plan; loading both as one review history is a fixture misuse and must fail.

Model-judgement vectors (for example nuanced craft/semantic judgements) are recorded as model-evaluation cases. Deterministic CI must not fake them with keyword matching merely to satisfy a named negative vector. **NV03 implied access is explicitly `recorded_model_eval`** because implied access is an adjudicated semantic blocker, not a deterministic keyword rule.

A writing-craft complaint received through Operator Repair follows the same principle: **repair from the earliest layer actually wrong, but no earlier**. Episode feedback may nominate a systemic editorial-improvement candidate but may not silently mutate Writing Craft v0.1, Character Bible v0.1.4, or canonical prompts/policies.

## 9. Hashing v0.1.4 base contract and bounded additive fixture decisions

### Layer A - base implementation contract

Hashing, Fingerprints & Text Spans v0.1.4 (SHA-256 `73cfc4727ce375df0a402c38b9a9044ceb6a1015ce0bcbeaf97433f6986f6d60`) is the base implementation contract. ### Layer B - later accepted bounded additive fixture decisions

Source: the accepted I2B technical adjudication and the frozen technical-resolution records shipped inside Fixture v0.4.5 (`provenance/frozen/i2b_v2/technical_resolution_record_v1.md`, SHA-256 `3f8a760aa106e238d262132ab396cc3a99f71c72768a2f6a72b14c65bd7f78c3`; `provenance/frozen/technical_resolution_record_v2.md`, SHA-256 `7a682cc5e17eda228e8711f10fb6214723550d3516cddebc995753e8a520de9c`; version 2 inherits version 1 sections 2.1-2.5 unchanged and records the CONFIG-330 corrected successor). These are additive decisions that apply only to the content of Fixture v0.4.5. They are fixture-specific, are not Hashing v0.1.4 text, and are not product-wide policy. No Hashing v0.1.5 exists.

1. **`evidence-package-scope-v1`.** Projection = exactly the eight `manifest.scope` fields, values and array order preserved: `competition_ids`, `entity_ids`, `event_ids` (ordered arrays of nonblank strings); `locale`, `scheduled_default_mode`, `target_publication_slot_ref` (nonblank strings); `scope_type` (literal `event`); `show_id` (governed UUID resolving to the bound show). Any other scope type or unrecognized field is rejected. `scope_hash = lower_hex(SHA256(UTF8("evidence-package-scope-v1\n") || canonical_json_bytes(scope_projection)))` using the Hashing v0.1.4 §1 canonical serializer, exactly one LF after the domain, no BOM, no trailing LF, no wrapper. The package hash keeps selecting `manifest` and excludes this envelope digest. Fixture value `ecb1eb2b675a9e383dfe88e6311f8cc88cc97eb17183df9a8cae935d8d1f8979`; captured bytes `provenance/captured/scope_projection.bytes` (SHA-256 `eee3d6c86f3f6a7afb75dcda3faf89fde158a3a560de70b97379385061cdd49e`).
