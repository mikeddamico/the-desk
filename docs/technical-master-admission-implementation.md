# Fixed technical master admission

The literal contract and independent expected vectors are in [technical-master-admission.md](technical-master-admission.md). The new source record, authored WAVs and vector packet are a separate synthetic test corpus. They do not amend Fixture v0.4.6, its v3 recipe or the existing six fingerprint projections.

`evaluateTechnicalMaster` accepts only the fixed four-field invocation. Acquisition owns either the new pinned authored corpus or the actual old committed constructor pair and independent historical selection/configuration records. The evaluator recomputes map, recipe, selected-input and Assembly bindings, then applies format, configured/planned duration, required block order, decode, reported integrated loudness, silence and final snapshot checks. It removes its captures and any old constructed pair before returning. A result describes captured facts only; all eight authority and clearance fields remain false.

The old master must refuse as `duration_below_configured_minimum` before inspection. Its 240-second target and 60–330-second band remain authoritative. The positive corpus uses an explicit test-only plumbing policy. It supplies no product loudness, silence or distribution defaults.

Inspection retains the existing supply registration and closure checks. Its new fixed argv comes only from the pinned inspection profile; the constructor's argv is unchanged. The private process owner copies the existing bounded capture pattern rather than exposing an arbitrary runner. Input files are exclusive, fsynced and read back; captured and staged hashes are checked immediately before launch and afterward. Complete decode packet hashes and byte counts must match the captured PCM. A unique final loudness summary is parsed at integer deci-LU precision. A container must be observed exited, not running, PID zero, error empty, exit zero and not OOM, then waited, reinspected and removed. Cleanup failure retains ownership and blocks another admission. Deadlines refuse bounded actions; they do not establish a hard wall or VM resource quota.

Allocation admission is conservative: source captures, including the master, are capped at 12 MiB; a single staging/readback buffer is at most 8 MiB; at most 2 MiB of captured streams and their bounded encoding/concatenation copies coexist. JSON reads are sequential and individually capped at 256 KiB. The profile's 32 MiB owned byte-buffer ceiling is checked before fixed acquisition allocations; this accounting excludes inherited verified pack caches, strings, JS objects, native and daemon memory. No decoded PCM copy or output file is created.

There are twelve top-level groups in `technical-master-admission.test.ts`. The two genuine media cases run under `technical-master` and the ordinary rest route. The literal `technical-master-pure` preparation route selects the same file and skips exactly those two cases; it is useful for ten mechanics groups and is never full acceptance. It cannot select arbitrary paths or patterns. Inspection fault controls replace only the private Docker spawn boundary and do not execute a container. The existing 16 constructor and 34 native cases are unchanged. Normal full acceptance expects 8,717 tests, with 3,809 rest and 4,908 writer tests in 82 selected files (83 tracked, including the focused harness).

Before any media release, review the actual candidate bodies and the exact bound invocation. The source-inferred FFmpeg header/summary grammar and positive acoustic outcome remain unmeasured. An actual mismatch is a contract finding; do not tune the parser, fixture, flags or policy to make it pass. A later authoritative gate, durable artifact readback, transaction/idempotency design and lifecycle transition require separate review. This evaluator does not complete Handoff steps 15 or 21.

The inspection owner begins before the first Docker client. Uncertain preflight or nested termination-client reaping keeps the admission latch even after daemon settlement; scratch/name preparation is inside the same cleanup owner. Registration and staged master reads still require the invoking UID. For only `decoded.sha256`, writer provenance instead comes from the fresh canonical caller-owned private root/work directory, exact absent-before-launch basename and sole fixed admitted container, followed by positive container settlement/removal. The directory identity and private mode are rechecked around the generated read, with no additional files and the readonly master unchanged. The generated file must be no-follow opened, regular, single-linked, exactly 72 bytes and not writable by group/others; device/inode/UID/GID/link/mode/size/mtime/ctime stay stable across its descriptor reads. Namespace-local UID/GID are observations, not root authentication or an allowlist.

This explicitly replaces the nonportable task-view UID 0 assumption. Linux can report an overflow ID for unmapped IDs; that many-to-one representation is not writer identity ([user_namespaces(7)](https://man7.org/linux/man-pages/man7/user_namespaces.7.html)). The first actual proof's missing hash stat does not establish its exact failed predicate; the adjustment is not a claim that UID caused that historical failure. It uses the existing cooperative fixture/owned-process model and does not authenticate hostile privileged host activity. No namespace, daemon, privilege, policy, decoder or runtime-profile setting changes.

Only the positive genuine test observes the real generated-file open and at most two actual descriptor-stat returns plus read count/request/returned lengths, without modifying receiver, arguments or results. The existing bounded raw receipt includes namespace-local metadata, directory observations and named admission predicates; incomplete observations are labelled and do not imply an unobserved predicate was executed. Observation errors fail test evidence after preserving the actual typed result. All temporary test spies/methods are restored.

The existing pure groups include all eight frozen dependent mutation vectors, source duplicate-key and oversized-JSON refusals before trust/allocation, an aggregate source-buffer refusal using aliased bounded inputs, isolated-module permanent-latch controls and fixed registration/staged/generated-file stat-shape faults, stable UID 0 and unmapped-looking generated UID controls, and private-directory replacement/permission controls. Module isolation is test-only; there is no production reset. The namespace-local generated UID/GID in those fake controls are simulated explicitly and do not establish real Docker writer identity.
