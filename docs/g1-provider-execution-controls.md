# G1-A: controlled non-network provider execution

Cancellation inside `finish` is checked before starting the record command: report ambiguous/provider_observation_canceled, keep perform=performed and outcome_record=not_attempted. A finish failure stays the first diagnostic even if finish also cancels. Once recording starts, cancellation does not race SQL or release its active connection: await unchanged runCommand and preserve its acknowledged committed event or unknown acknowledgement. Committed receipt recovery remains authoritative.

New live/paid execution is unavailable. `executeProviderCall` is the sole perform entry and refuses new work without an explicit validated non-network controls context. Public `reserveProviderCall` remains a historical ledger API; its result alone never authorizes execution.

The controls context is trusted application/test construction: mode `non_network`, DESK_ENV development/test, PROVIDERS_ENABLED false, GENERATION_KILL_SWITCH false and a positive integer PROVIDER_CALL_TIMEOUT_MS at most 2147483647. Optional config defaults to 30000ms only for development/test. Staging/production cannot select this path. Provider name, free pricing and zero-cost receipts do not grant exemption. This is neither hostile in-process authentication nor a network sandbox; TypeScript objects are forgeable.

Observer/reservation preflight precedes database work. Controls are snapshotted once without invoking accessors. The new-work guard runs inside the reservation decision after existing identity classification and before INSERT. Exact completed recovery ignores missing/disabled controls; unfinished/held/conflicting identities preserve the existing no-takeover semantics. Only the caller whose own acknowledged committed command returns created may invoke.

Cancellation observed before the committing callback result refuses and rolls back. The unchanged command helper cannot atomically prevent cancellation after that decision but before COMMIT: a reservation may commit; cancellation observed before perform prevents invocation and leaves it unfinished. After invocation, thrown perform, timeout or cancellation is ambiguous. No fabricated terminal/retryable/canceled event, retry, takeover or exposure release occurs.

The finite referenced observation timer and monotonic completion-time check bound caller observation while the event loop runs. Optional second adapter argument is a cooperative AbortSignal; one-argument adapters remain valid. Abort does not prove provider cancellation or shutdown. Owned timer/listeners are cleaned. Late resolution/rejection is consumed without finish, SQL or accounting; only existing explicit bound-evidence reconciliation may record the original call's outcome. No background accounting task exists.

Execution exceptions contain only owned codes, correlation, stage, projected error class and known/unknown commit state; no raw cause or error children. Operational result errors exclude raw provider/finish/SQL content. Canonical internal receipts retain exact usage, references, timestamp and numeric scale; this is not a claim that every receipt string is sanitized. Shared command/internal-cause APIs, pool and logger contracts are unchanged.

Bounds exclude pool checkout/transport/COMMIT/ROLLBACK/server cancellation, arbitrary SDK/socket shutdown and process-wide wall-clock guarantees during event-loop blocking. No live integration, schema/grant change or lifecycle projection is included. G1-B reserved-cost certificate, price/accounting/currency/policy/server-time admission, budgets, concurrent paid/rate/retry/reroll ceilings and generated-seconds/per-block controls remain open. G1-A does not close G1, G5, Completion A/B or Build 2.
