## SQL normalization and row identity

SQL-COLUMN-MAP.json is the complete closed table-to-primary-key and column-order map. Query precisely those columns; reject missing or extra columns, absent values and duplicate column names. primary_key is the decoded row's named UUID PK, in canonical lowercase form, and must equal the envelope primary_key exactly. It is not a caller label or a row-array index. Reject table names outside the applicable allowlist.

Decode SQL values by the supplied column type: UUIDs as lowercase canonical UUID strings; text as NFC strings without trim; sha256_hex as exactly 64 lowercase hexadecimal characters; lifecycle_state as the exact existing SQL enum literal; booleans as JSON booleans; integer/bigint as exact safe JSON integers, rejecting fractions, negative zero, overflow and lossy driver coercion. PostgreSQL integer lexical input may be converted only after full signed-base10 syntax/range validation. For timestamptz columns, retain full microsecond precision: convert the represented instant to UTC, render YYYY-MM-DDTHH:mm:ss[.fraction]Z with at most six fractional digits and trailing fractional zeros removed (omit fraction if zero); reject invalid dates or unavailable/lost precision. Do not round through a millisecond Date when precision would be lost. This is SQL-column transport normalization, not a change to timestamp strings inside existing artifact payloads or their established hashes.

Every nullable SQL column is present with explicit JSON null when SQL NULL. JSON/JSONB columns decode as actual JSON values, not text: NFC strings/keys, code-point-sorted keys, ordered arrays, safe integers, no duplicate normalized keys, no fractional numeric values, no coercion. Unknown nested fields are refused under that column's pinned owner payload schema. In this fixed positive, JSON/JSONB values retain the exact expected types from AUTHORED-NORMALIZED-ROWS (including JSON strings such as canonical_content and claim values); SQL NULL or top-level JSON null refuses; intentional nested JSON null (for example intent.timing_anchor) remains null. No SQL-NULL/JSON-null ambiguity is accepted. Text that happens to contain JSON is not parsed except canonical_row as specified below.

canonical_row is the exact UTF8 encoding of canonical_json(decoded column projection) stored as a JSON string in the row envelope. It has no BOM, whitespace outside strings or final LF. Parse that string using the same strict JSON/normalization rules, require the exact SQL-column key set, and reserialize it; byte-for-byte equality is mandatory. Key order in the source SQL projection list does not override canonical object key sorting. The exact row envelope is {table,primary_key,canonical_row,row_sha256}. row_sha256 = raw SHA256(UTF8(canonical_row)); NO domain, prefix, LF, table-name text or envelope bytes. Table and PK remain bound in the containing array/envelope; changing either is not legitimized by a matching row hash.
